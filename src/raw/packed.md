# Literal packed boot

`packed.inc` contains authored 32-bit instruction bytes. After BIOS validates the
stored payload, a 25-byte stub at 0x100000 copies decoder and stream to 0x80000.
The 162-byte decoder expands into 0x100000, checks exact length and original FNV32,
then jumps to the decoded CPU entry. Both stages have separate symbols/mode ranges.
The stream uses our documented boot packing grammar: tag 0..127 copies tag+1
literal bytes; tag 128..255 copies (tag&127)+3 bytes at a following little-endian
16-bit backward distance. Overlapping forward copies are permitted.

Each token checks input and output bounds; distances must be nonzero and within
the produced prefix. Truncation, overflow, wrong size/hash and trailing input halt
with IF clear. The writer bounds all source, relocation and decoded ranges within
the existing BIOS RAM checks. Decoder bytes are never generated by the encoder.
Provenance: this project's boot packing interface and Intel instruction encodings;
no guest instructions were extracted from compiled code.

From osenv:

```sh
python3 -m osenv raw-build --project ../oslab --output build/raw-packed --packed
python3 -m osenv raw-test --build build/raw-packed --output local/raw-packed-checks
python3 -m osenv.raw_packed_test --build build/raw-packed --output local/raw-decoder-checks
python3 -m osenv raw-size --build build/raw-packed --output local/raw-size
```

The host optimal encoder emits its complete suffix-cost certificate. Accounting
independently reconstructs source/image bytes, decodes the stream and recomputes
that certificate. The proof is confined to the fixed decoded kernel, this codec,
this adapter and sector alignment; it is not a global machine-program minimum.
